# edu-tools — AGENTS.md
Status: Draft (2026-09-23)

## System summary (C4 L1)
EduTools автоматизирует рутинные административные операции в системах УрФУ. Пользователь описывает задание на листе Google Таблицы, а web-приложение выполняет его в браузере от имени пользователя. Есть режим try (без записи) и режим save. Собственного бэкенда нет; к системам УрФУ браузер ходит через CORS-proxy. Отдельно есть Telegram bot, который сохраняет ресурсы в Notion.

Акторы: преподаватели, сотрудники, поддерживающие образовательные программы, и сотрудники деканатов (web); разработчик (Node-скрипты, деплой); пользователь Telegram-бота.

Внешние системы: Google Sheets/OAuth, БРС, ИТС, TeamProject, Partner, Notion, Telegram, Yandex Cloud (хостинг).

## Workflow for agents
1. **Перед задачей** открыть [`.memory-bank/index.md`](.memory-bank/index.md) и пройти по индексам до нужного раздела: спека задания, интеграция, эпик/фича. Документы со статусом `Active` — согласованный норматив, `Draft` — черновик, который можно уточнять.
2. **Код и документация — вместе.** Если меняется поведение, формат листа, интеграция или план, в том же коммите обновляется соответствующий SSoT в `.memory-bank/`. Новое существенное решение оформляется ADR.
3. **Новые документы** — по правилам MBB: строка статуса с датой, аннотированные ссылки, ссылка из индекса папки.
4. **Перед «готово»** — базовые проверки из [verification matrix](.memory-bank/plans/verification-matrix.md): `npm run lint`, сборка затронутых частей, `npm run docs:check`, если менялся меморибанк.
5. **Язык:** общение с пользователем и документация — на русском; код, идентификаторы и сообщения коммитов — на английском.

## Key rules
- `brs-extensions/` — только референс для переноса функциональности в edu-tools. Код не дописываем и не рефакторим.
- Не коммитить учётные данные (токены, куки, sid) в код. Секреты — только `.env` и `secrets/`.
- Логика заданий живёт в `src/tasks` / `src/actions` / `src/apis`, а не в UI (см. architecture guardrails).
- При противоречиях между документами меморибанка приоритет у MBB.
- Коммиты по фичам и эпикам помечаются тегами `[FT-XXXX]` / `[EP-XXX]`.

## Memory bank (SSoT)
Меморибанк находится в `.memory-bank/` и является SSoT по требованиям/решениям/планам.

Ссылки (аннотированные):
- [`.memory-bank/index.md`](.memory-bank/index.md) — главный индекс меморибанка (куда идти за spec/plans/adr/mbb). Читать, чтобы быстро найти SSoT по теме и не создавать orphan документы.
- [`.memory-bank/mbb/index.md`](.memory-bank/mbb/index.md) — «библия» меморибанка: правила SSoT/аннотированных ссылок/duo pattern/индексов/шаблонов. Читать перед созданием новых документов, чтобы соблюдать стандарты и не плодить дубли.
- [`.memory-bank/spec/project/repo-structure.md`](.memory-bank/spec/project/repo-structure.md) — структура репозитория по папкам и подпроектам. Читать, чтобы правильно раскладывать код.
- [`.memory-bank/spec/index.md`](.memory-bank/spec/index.md) — спецификации (WHAT). Читать, чтобы реализовывать правила домена и интеграции корректно.
- [`.memory-bank/adr/index.md`](.memory-bank/adr/index.md) — ADR (WHY). Читать, чтобы не отменять решения случайно и понимать компромиссы.
- [`.memory-bank/plans/index.md`](.memory-bank/plans/index.md) — roadmap, эпики/фичи, playbook реализации. Читать, чтобы делать работу вертикальными слайсами с проверками.
