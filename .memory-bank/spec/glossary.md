# Glossary
Status: Draft (2026-09-23)

Цель: единые термины. Если термин не определён здесь — добавляем сюда, а не «как получится в коде».

## Системы УрФУ
- **БРС** — балльно-рейтинговая система (`brs.urfu.ru`): дисциплины, техкарты, оценки студентов.
- **ИТС** — «Индивидуальная траектория студента» (`its.urfu.ru`): система, которая помогает организовать обучение студентов по индивидуальным образовательным траекториям. В EduTools используется для проектов и записи студентов в команды.
- **TeamProject** — система проектного обучения (`teamproject.urfu.ru`): рабочие пространства проектов, итерации, оценки.
- **Partner** — портал проектов от партнёров (`partner.urfu.ru`), источник паспортов проектов.

## Задания
- **Табличное задание (table task)** — лист Google Таблицы с параметрами и строками, описывающий операцию. См. [Table task format](domain/table-task-format.md).
- **Тип задания** — значение параметра `task`, определяет исполнителя (например, `SendCuratorMarks`).
- **Исполнитель (executor)** — код, выполняющий задание одного типа.
- **Дополнительные колонки (extra columns)** — колонки листа с заголовком на `$$`: упорядоченный набор, смысл которого определяет тип задания (например, контрольные мероприятия при переносе баллов). В отличие от них, колонки на `$` — объявленные поля задания. См. [ADR-0006](../adr/ADR-0006-extra-columns.md).
- **Try / Save** — пробный прогон без записи во внешние системы / прогон с записью. В UI: «Попробовать сделать хорошо» / «Сделать хорошо».

## Учебный процесс
- **Учебный год (academicYear)** — `2024/2025`; в заданиях используется первый год.
- **Семестр (semester)** — `fall` (1) / `spring` (2).
- **Курс (studyYear)** — год обучения студента (1–4…).
- **Дисциплина** — учебная дисциплина в БРС; **нагрузка дисциплины (disciplineLoad)** — идентификатор конкретной реализации дисциплины для групп в семестре.
- **Модуль (isModule)** — дисциплина, пришедшая из ИТС (модульная), в отличие от обычной.
- **Техкарта (технологическая карта)** — структура оценивания дисциплины в БРС: типы занятий, нагрузки, коэффициенты, промежуточная аттестация. Техкарту нужно заполнить и **согласовать**.
- **Нагрузка (load)** — контрольное мероприятие в техкарте с максимальным баллом (сумма по типу занятий = 100).
- **Коэффициенты (factors)** — веса текущей и промежуточной аттестации и вес типа занятий в итоговой оценке.
- **Промежуточная аттестация** — зачёт/экзамен; в техкарте привязывается к одному типу занятий.
- **Контрольное мероприятие (control action)** — мероприятие дисциплины в БРС, за которое студенту выставляется балл («домашняя работа», «экзамен»). Задаётся техкартой: каждой нагрузке техкарты соответствует контрольное мероприятие.
- **Причина отсутствия (student failure)** — отметка в БРС вместо балла: «Не явился», «Не допущен», «Академический отпуск» и т. п.; «-» — причины нет.
- **Перенос баллов** — выставление баллов студентов по контрольным мероприятиям дисциплины в БРС из таблицы преподавателя.

## Проектное обучение
- **Проект** — тема проекта в ИТС/TeamProject.
- **Экземпляр проекта / команда (projectInstanceNumber)** — номер команды, работающей над проектом; в ИТС — подгруппа проекта, в TeamProject — рабочее пространство (workspace).
- **Итерация** — этап работы команды с датами начала и окончания; за итерацию выставляются оценки.
- **Оценка куратора** — балл, который куратор выставляет студенту за итерацию.

## Планирование
- **Эпик (EP-XXX)** и **фича (FT-XXXX)** — единицы плана работ. См. [How we plan](../plans/how-we-plan.md).
