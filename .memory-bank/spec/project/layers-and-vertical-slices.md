# Layers & vertical slices
Status: Draft (2026-09-23)

Цель: держать **слои** (для простоты и тестируемости) и одновременно строить продукт **вертикальными слайсами** (каждая фича — работающий сквозной кусок).

## Слои сейчас (as-is)
- **Delivery:** Web UI (`src/components` + `src/stores`), Node-скрипты (`src/main.ts`), Telegram bot (`src/bot.ts`).
- **Task engine** (`src/tasks`): чтение листа, маршрутизация по типу задания, исполнители.
- **Actions** (`src/actions`): многошаговые операции с доменными правилами (например, заполнение техкарты).
- **Adapters** (`src/apis`): клиенты внешних систем, абстракция `GoogleApi`.

Ограничения текущего состояния:
- в исполнителях смешаны разбор параметров, доменные правила, вызовы API и логирование;
- API-клиенты — конкретные классы без интерфейсов, поэтому их нельзя подменить фейками в тестах;
- результат выполнения — только текстовый лог, ошибки — строки лога;
- доменные правила нельзя проверить без обращения к реальным системам.

## Целевые слои (target, [EP-003](../../plans/epics/EP-003-layers.md))
- **Core (domain logic):** чистые функции без I/O: разбор параметров задания, вычисление желаемого состояния и расхождений (план изменений), правила (распределение нагрузок техкарты, сопоставление студентов и команд). Здесь живут инварианты.
- **Ports:** интерфейсы внешних систем в терминах, нужных core. Реализации — реальные адаптеры и фейки для тестов.
- **Use cases (executors):** оркестрация: прочитать состояние через порты → вычислить план в core → применить (только в save) → сообщить результат структурированными событиями.
- **Adapters:** реализации портов для БРС, ИТС, TeamProject, Partner, Google, Notion.
- **Delivery:** Web UI, CLI, bot — тонкие: собирают ввод и учётные данные, вызывают use case, отображают события. Если когда-нибудь появится бэкенд, он станет ещё одним delivery/адаптером, а core не изменится.
