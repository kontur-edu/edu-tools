# Task: PutMarksToBrs
Status: Draft (2026-09-24)

Переносит баллы студентов по контрольным мероприятиям дисциплины из листа в БРС и выставляет причины отсутствия. Код: исполнитель — `src/tasks/PutMarksToBrsTask.ts`, логика переноса — `src/actions/putMarksToBrsAsync.ts` → `putMarksForDisciplineAsync.ts`.

## Параметры
- `discipline` — обязательный, название дисциплины в БРС (сравнение нормализованное).
- `academicYear` — обязательный, `2024/2025`; используется первый год.
- `semester` — обязательный, `fall` / `spring`.
- `studyYear` — курс, целое; не задан → `0` = все курсы. Задан, но не целое → задание не выполняется.
- `isModule` — bool, по умолчанию false (дисциплина из ИТС).
- `defaultFailure` — русская подпись причины отсутствия из БРС («Не явился», «Не допущен», …), которая ставится активным студентам БРС, которых нет в листе; по умолчанию «-» (причины нет). Нераспознанная подпись — «-».
- `save`.

## Колонки
- `$group` — группа в БРС, `$student` — фамилия и имя (начало ФИО в БРС) — обязательные; строка без них пропускается, в лог пишется, сколько студентов найдено в скольких строках.
- `$failure` — причина отсутствия (подписи — как у `defaultFailure`); пусто или не распознано — «-».
- `$$<контрольное мероприятие>` — балл по мероприятию. Правила `$$`-колонок — [ADR-0006](../../../adr/ADR-0006-extra-columns.md); читать, чтобы понимать повторы и названия с точками. Нужна хотя бы одна. Название сравнивается с мероприятиями БРС нормализованно; одинаковые названия сопоставляются с одноимёнными мероприятиями БРС по порядку, и их число должно совпадать.

## Поведение
Для каждой дисциплины БРС с таким названием (по году, семестру, курсу, `isModule`) и каждой её группы, для которой в листе есть студенты:
1. Каждая `$$`-колонка сопоставляется с мероприятием БРС. Не нашлось или неоднозначно → группа пропускается (в лог — какие мероприятия известны).
2. Студент листа сопоставляется с активным студентом БРС по началу ФИО; не нашлось или больше одного — студент в лог «Can't merge».
3. Балл отличается от БРС и не равен 0 → выставляется; причина отсутствия отличается → выставляется.
4. Активным студентам БРС, которых нет в листе, ставится `defaultFailure`.
5. В save после записи пересчитываются итоги дисциплины (`updateAllMarksAsync`). В try в БРС ничего не пишется — [ADR-0003](../../../adr/ADR-0003-try-save-modes.md); читать перед изменением записи в БРС.

## События
Модель и рендер — [Execution events](execution-events.md); читать перед изменением сообщений лога. Отчёт переноса — строки без статуса: `# …` → `heading`, пустая → `separator`, остальные → `note` (статусы по студентам — вне объёма, см. roadmap «Перенос brs-extensions»). Итог:
- параметр отсутствует или не распознан, нет `$$`-колонок → `note` с ❗ (`- semester required❗`) и `error` со `stopped`, scope — имя задания;
- исключение во время переноса (сеть, авторизация) → `error` со `stopped`, scope — имя задания;
- иначе → `finished`; `summary.ok = true`.

Известное ограничение: пропуск группы из-за несопоставленного мероприятия и «дисциплина не найдена» видны только в отчёте и не делают прогон не `ok`.

## Старый лист → новый
Старая раскладка (`buildAutoMarksConfigAsync`, `src/putMarks.sample.ts`) больше не запускается; лист переводится вручную.

| Старый лист | Новый лист |
|---|---|
| колонка «Группа в БРС» | `$group` |
| колонка «Фамилия Имя в БРС» | `$student` |
| колонка «Причина отсутствия» | `$failure` |
| колонки мероприятий между ФИО и «Причина отсутствия» | `$$<мероприятие>` (где угодно на листе, порядок слева направо) |
| «Названия параметров» / «Значения параметров» | `$keys` / `$values`, плюс `task = PutMarksToBrs` |
| «Дисциплина» | `discipline` |
| «Учебный год» (`2024/2025`) или «Год» | `academicYear` (`2024/2025`) |
| «Семестр»: осенний / весенний | `semester`: `fall` / `spring` |
| «Курс»: число / «все курсы» | `studyYear`: число / не задан |
| «ИТС»: да | `isModule`: `true` |
| «Причина отсутствия по умолчанию» | `defaultFailure` |
