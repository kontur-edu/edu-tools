# Task: CreateTechnologyCards
Status: Draft (2026-09-23)

Заполняет техкарты в БРС по типовым правилам и, если запрошено, согласует их.

## Параметры
- `save`.

## Колонки (все обязательные, иначе строка пропускается)
`$disciplineLoad`, `$discipline`, `$isModule`, `$academicYear`, `$studyYear`, `$semester` (число 1/2), `$agreed` (запросить согласование).

## Поведение
Техкарта ищется в БРС по `disciplineLoad` в выборке (academicYear, semester, studyYear, isModule). Не найдена → ❌ в лог, переход к следующей строке.

Правила заполнения (`fillTechnologyCardAsync`):
1. Уже согласованная техкарта не меняется.
2. **Промежуточная аттестация:** если тип не выбран, выбирается по приоритету: лекции → практики → первый доступный.
3. **Нагрузки** по каждому типу занятий (текущая аттестация):
   - нагрузок нет → добавляется одна (`лабораторная работа` / `практическая работа` / `домашняя работа`) на 100;
   - сумма ≠ 100 → 100 делится поровну (с округлением вниз, остаток уходит последним).
4. **Коэффициенты:** для типа промежуточной аттестации — текущая 0.5 / промежуточная 0.5, для остальных — 1.0 / 0.0. Вес типа занятий — 1 поровну между типами с точностью 0.1 (остаток у последнего).
5. **Проверка и согласование:** если БРС считает техкарту заполненной и разрешает согласование, а `agreed` = true — техкарта согласуется.

В режиме try проверка корректности показывает состояние до изменений, поэтому ошибки в try ожидаемы.

## События
Модель, статусы и рендер — [Execution events](execution-events.md); читать перед изменением сообщений лога. Scope — `disciplineLoad` техкарты.
- установлена аттестация, добавлена или обновлена нагрузка, обновлены коэффициенты, техкарта согласована → `changed`; уже установлено / уже согласована → `unchanged`;
- техкарта не найдена, не удалось получить коэффициенты / данные аттестации / тип аттестации → `error` со `stopped`; не удалось получить нагрузку по типу занятий → `error`;
- итог проверки БРС → `verdict`: заполнена корректно, может быть согласована — `ok`; согласование не запрошено, можно запросить, ошибки в try — `attention`; ошибки в save — `failed` (делает прогон не `ok`).
