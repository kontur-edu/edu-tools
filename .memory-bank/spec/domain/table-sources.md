# Table sources: Google Sheets и CSV
Status: Draft (2026-09-23)

**Состояние:** сейчас задание читается только из Google Таблицы (`TableTaskReader` поверх `GoogleApi`). CSV как источник и конвертация появляются в EP-001 (FT-0015, FT-0016); ниже — целевая спецификация.

Зачем: запускать и тестировать задания без учётной записи Google ([ADR-0005](../../adr/ADR-0005-csv-table-source.md)). Лист задания и CSV-файл — два представления одного и того же: таблицы строк с одинаковой разметкой ([Table task format](table-task-format.md)).

## Модули (каждый тестируется отдельно)
1. **CSV codec** — чистые функции `текст ⇄ string[][]`, без файловой системы.
2. **Table task parser** — чистая функция `string[][] → TableTask`: вся разметка (`$`-колонки, `$keys`/`$values`, пространства имён, нормализация имён) разбирается по сетке значений, независимо от источника. Сейчас эта логика смешана с чтением диапазонов в `TableTaskReader`.
3. **Table source** (порт) — прочитать сетку значений листа, записать блок значений с позиции (колонка, строка). Реализации:
   - Google sheet (через `GoogleApi`, браузер и Node);
   - CSV-файл (Node): входной файл только читается, запись идёт в отдельный выходной файл (см. ниже);
   - in-memory (unit-тесты).
4. **Converter** — Google ⇄ CSV: прочитать сетку из одного источника и записать в другой.

## CSV format
- UTF-8; BOM при чтении игнорируется, при записи не добавляется.
- Разделитель `,` (как в выгрузке Google Sheets «CSV»). Другие разделители не поддерживаются.
- Экранирование по RFC 4180: значения с разделителем, кавычками или переводом строки берутся в `"…"`, кавычка удваивается; переводы строк — `\n` и `\r\n`.
- Строка 1 — заголовок листа, как в Google Таблице. Один CSV-файл = один лист.
- Все значения — строки; типы определяет разбор задания, как для Google.
- Существующий `FileApi.readFromCsv` этим правилам не соответствует (нет кавычек, только `\r\n`) и заменяется CSV codec.

## Равенство источников (инвариант)
Одна и та же сетка значений из Google и из CSV даёт одинаковый `TableTask` и одинаковый результат выполнения. Ограничения чтения Google (например, параметры только в первых 100 строках) реализуются в разборе, а не в источнике, чтобы не расходиться с CSV.

## Конвертация
- **Google → CSV:** выгружаются отображаемые значения всего листа; формулы и форматирование теряются (в CSV попадают их значения).
- **CSV → Google:** значения записываются как есть (`RAW`), без автоопределения типов, чтобы `2024/2025` или `1, 2` не превратились в даты или числа. Непустой целевой лист перезаписывается только при явном флаге.
- Круговая конвертация (Google → CSV → Google, CSV → Google → CSV) сохраняет значения ячеек.

## Запись результатов заданий
Входной CSV-файл **никогда не изменяется**. Если задание пишет на лист (например, `ExportTechnologyCards`):
- **с `--out <file.csv>`** — запись идёт в выходной файл. В нём лежит весь лист в том виде, каким он стал бы после записи: входная сетка плюс записанные блоки. Такой файл можно сравнить с эталоном в тесте или импортировать обратно в Google Таблицу;
- **без `--out`** — запись не выполняется, выдаётся событие со статусом `warning` («укажите `--out`, чтобы сохранить результат записи на лист»); значения, которые были бы записаны, передаются в `details`.

Выходной файл пишется в обоих режимах (try и save): это локальный файл, а не данные внешней системы, поэтому правило try/save на него не распространяется.

## Где доступно
CSV — в Node (CLI, тесты). В web пока только Google Таблицы; загрузка CSV в web — вне текущих планов.
