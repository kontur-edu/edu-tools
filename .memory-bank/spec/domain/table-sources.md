# Table sources: Google Sheets и CSV
Status: Draft (2026-09-24)

**Состояние:** модули 1–3 реализованы (FT-0015): CSV codec — `src/helpers/csv.ts`, разбор — `src/tasks/tableTaskParser.ts`, порт `TableSource` с Google- и in-memory-реализациями — `src/tasks/TableSource.ts`, CSV-файл — `src/apis/NodeCsvFile.ts`. Задание читается `readTableTaskAsync(source)`; `TableTask.source` — лист, из которого оно прочитано, туда же пишет `TableTaskWriter`. Google-источник читает весь лист одним запросом (раньше было два: `A1:ZZ100` и колонки между крайними `$`-колонками), поэтому `$`-колонки правее `ZZ` теперь тоже участвуют в задании; имя листа в диапазонах берётся в кавычки по A1-нотации. Запись на лист (FT-0018): in-memory и CSV-источник пишут в сетку в памяти чистой функцией `writeBlockToGrid` (`src/tasks/TableSource.ts`), CLI сохраняет сетку CSV-источника в `--out` (`writeCsvFile`); без `--out` CLI оборачивает CSV-источник в `WriteSkippingTableSource`, который вместо записи выдаёт `warning`. CLI (`task run`, FT-0004) выбирает источник по аргументу: URL листа или путь к CSV. Converter — FT-0016.

Зачем: запускать и тестировать задания без учётной записи Google ([ADR-0005](../../adr/ADR-0005-csv-table-source.md)). Лист задания и CSV-файл — два представления одного и того же: таблицы строк с одинаковой разметкой ([Table task format](table-task-format.md)).

## Модули (каждый тестируется отдельно)
1. **CSV codec** — чистые функции `текст ⇄ string[][]`, без файловой системы.
2. **Table task parser** — чистая функция `string[][] → данные задания` (`TableTaskData`; `TableTask` = данные + источник): вся разметка (`$`-колонки, `$keys`/`$values`, пространства имён, нормализация имён) разбирается по сетке значений, независимо от источника.
3. **Table source** (порт) — прочитать сетку значений листа, записать блок значений с позиции (колонка, строка). Реализации:
   - Google sheet (через `GoogleApi`, браузер и Node);
   - CSV-файл (Node): входной файл только читается, запись идёт в отдельный выходной файл (см. ниже);
   - in-memory (unit-тесты).
4. **Converter** — Google ⇄ CSV: прочитать сетку из одного источника и записать в другой.

## CSV format
- UTF-8; BOM при чтении игнорируется, при записи не добавляется.
- Разделитель `,` (как в выгрузке Google Sheets «CSV»). Другие разделители не поддерживаются.
- Экранирование по RFC 4180: значения с разделителем, кавычками или переводом строки берутся в `"…"`, кавычка удваивается; переводы строк — `\n` и `\r\n`.
- Строка 1 — заголовок листа, как в Google Таблице. Один CSV-файл = один лист.
- Все значения — строки; типы определяет разбор задания, как для Google.
- Прежний `FileApi.readFromCsv` (без кавычек, только `\r\n`) удалён: чтение CSV-файлов, в том числе списков студентов (`readStudentsAsync.fromCvs`), идёт через CSV codec.

## Равенство источников (инвариант)
Одна и та же сетка значений из Google и из CSV даёт одинаковый `TableTask` и одинаковый результат выполнения. Ограничения чтения Google (например, параметры только в первых 100 строках) реализуются в разборе, а не в источнике, чтобы не расходиться с CSV. Google обрезает хвостовые пустые ячейки строки, CSV — нет, поэтому разбор считает недостающую ячейку пустой (`''`). Проверяется тестом эквивалентности в `src/tasks/TableSource.test.ts`.

## Конвертация
- **Google → CSV:** выгружаются отображаемые значения всего листа; формулы и форматирование теряются (в CSV попадают их значения).
- **CSV → Google:** значения записываются как есть (`RAW`), без автоопределения типов, чтобы `2024/2025` или `1, 2` не превратились в даты или числа. Непустой целевой лист перезаписывается только при явном флаге.
- Круговая конвертация (Google → CSV → Google, CSV → Google → CSV) сохраняет значения ячеек.

## Запись результатов заданий
Входной CSV-файл **никогда не изменяется**. Если задание пишет на лист (например, `ExportTechnologyCards`):
- **с `--out <file.csv>`** — запись идёт в выходной файл. В нём лежит весь лист в том виде, каким он стал бы после записи: входная сетка плюс записанные блоки. Такой файл можно сравнить с эталоном в тесте или импортировать обратно в Google Таблицу;
- **без `--out`** — запись не выполняется, выдаётся событие со статусом `warning` («укажите `--out`, чтобы сохранить результат записи на лист»); значения, которые были бы записаны, передаются в `details`.

Выходной файл пишется в обоих режимах (try и save): это локальный файл, а не данные внешней системы, поэтому правило try/save на него не распространяется. Задание само решает, писать ли на лист: `ExportTechnologyCards` пишет только в save, поэтому в try выходной файл совпадает со входной сеткой, а `warning` без `--out` не выдаётся.

Правила записи блока в сетку в памяти (`writeBlockToGrid`, общие для in-memory и CSV; повторяют запись `RAW` на лист Google):
- блок пишется с позиции (колонка, строка); сетка расширяется до блока, результат — прямоугольная сетка (короткие строки дополняются `''`); пустой блок ничего не пишет;
- числа записываются строкой, `true` / `false` — как `TRUE` / `FALSE` (так их показывает и выгружает Google), `null` / `undefined` не меняют ячейку (как в Sheets API), объекты — JSON;
- без записи выходной файл содержит входную сетку как есть (без выравнивания строк); значения ячеек в обоих случаях совпадают;
- выходной файл пишется CSV codec'ом: UTF-8 без BOM, каждая строка завершается `\n`.

Событие `warning` без `--out`: `scope` и `details.range` — диапазон блока в A1-нотации (`D1:L3`), `details.values` — значения блока CSV-текстом (правила CSV format выше, строки через `\n`; `null` показывается пустой ячейкой, хотя при записи он ячейку не меняет): `details` — плоские значения, а CSV можно сразу сохранить в файл или вставить в таблицу.

## Где доступно
CSV — в Node (CLI, тесты). В web пока только Google Таблицы; загрузка CSV в web — вне текущих планов.
