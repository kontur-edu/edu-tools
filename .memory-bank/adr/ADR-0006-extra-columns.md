# ADR-0006 — Дополнительные колонки ($$) в табличном задании
Status: Active (2026-09-23)

### Context
Задание переноса баллов в БРС (`PutMarksToBrs`) должно принимать заранее неизвестный набор колонок: по одной на контрольное мероприятие дисциплины. Названия задаёт БРС, они бывают одинаковыми (три колонки «домашняя работа» сопоставляются с тремя мероприятиями по порядку) и содержат точки и цифры («Лаб. работа», «Контрольная работа 1»). Обычные `$`-колонки для этого не подходят: разбор хранит их по нормализованному имени, поэтому одинаковые колонки схлопываются, а точка читается как пространство имён.

Рассмотренные альтернативы:
- считать мероприятием любую `$`-колонку, кроме зарезервированных, — ненадёжно: опечатка в имени обычной колонки молча превращает её в мероприятие;
- запретить повторы и нумеровать колонки (`$домашняя работа 1`) — ломается, когда в БРС есть мероприятие с номером в названии.

### Decision
В формат табличного задания вводятся **дополнительные колонки** — колонки, заголовок которых начинается с `$$`. Это упорядоченный набор колонок, значения которых задание интерпретирует само:
- заголовок — текст после `$$` без крайних пробелов, без нормализации; нормализует ли его задание — решает задание;
- порядок слева направо сохраняется, повторы разрешены;
- пространств имён нет: точка — часть названия;
- строка пустая, только если пусты все её `$`- и `$$`-значения;
- задание, которое не ожидает дополнительных колонок, их игнорирует.

`$`-колонки остаются объявленными полями задания с прежними правилами.

### Consequences
- Плюсы: переменный набор колонок объявлен явно, обычные `$`-колонки не меняют смысла; повторы и произвольные названия работают без экранирования; механизм общий и доступен другим заданиям.
- Минусы / принятые риски: в формате два вида колонок, пользователю нужно знать разницу; смысл `$$`-колонок у каждого задания свой и описывается в спеке задания.
- Ограничение: `$$`-колонки не поддерживают пространства имён и типизированные значения на уровне формата — всё это делает задание.
