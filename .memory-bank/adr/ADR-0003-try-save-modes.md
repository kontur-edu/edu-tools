# ADR-0003 — Режимы try и save
Status: Active (2026-09-23)

### Context
Задания массово меняют данные в системах УрФУ (оценки, техкарты, записи студентов). Ошибки в листе (опечатка в ФИО, неверный номер команды, несуществующий проект) нужно найти до того, как что-то изменится.

### Decision
Каждое задание выполняется в одном из двух режимов:
- **try** — всё читается, сравнивается и логируется как при реальном выполнении, но записи во внешние системы не выполняются;
- **save** — то же самое с записью.
Рабочий цикл: try → исправить ошибки в листе → снова try, чтобы убедиться, что ошибок нет → save.

Правило касается данных во внешних системах и в листе-источнике. Локальные выходные файлы (например, `--out` при CSV-источнике) пишутся в обоих режимах: так в try сразу видно, что получится ([Table sources](../spec/domain/table-sources.md)).

### Consequences
- Плюсы: все ошибки видны заранее без изменения данных; безопасно экспериментировать.
- Минусы: каждая запись в исполнителе обязана быть под проверкой `save` — легко забыть (закреплено в guardrails); некоторые проверки внешней системы (например, корректность техкарты) в try показывают состояние до изменений.
- Вместе со сходимостью к желаемому состоянию делает повторные запуски безопасными.
