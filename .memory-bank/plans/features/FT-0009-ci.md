## Feature FT-0009 — CI
Epic: `EP-002`. Status: `Done` (2026-09-24). Исключение из DoD: ручная приёмка на GitHub не выполнялась — ни зелёного прогона workflow, ни проверок «падает `npm test`» и «падает `npm run typecheck`» из сценария ниже. Шаги `.github/workflows/ci.yml` пройдены только локально с `CI=true` на Windows; поведение на `ubuntu-latest` (в том числе регистр путей в импортах) не проверено.
Triage: `ready-for-agent`.
Blocked by: FT-0006.

### User value
Каждый push и PR проверяются автоматически, даже если pre-commit не установлен или обойдён. Статус проверки виден в GitHub до мержа.

### Deliverables
- Workflow GitHub Actions на push и pull request: `npm ci --legacy-peer-deps`, `npm run lint`, `npm run docs:check`, `npm run typecheck`, `npm run build`, `npm run web-build`, `npm test`.
- `npm run typecheck` нужен отдельным шагом: `build` исключает тесты из `tsc` (`tsconfig.json`), а Vitest типы не проверяет, так что ошибки типов в `*.test.ts` ловит только он ([ADR-0007](../../adr/ADR-0007-vitest-test-runner.md)). В pre-commit не входит: это долгая проверка.
- Node — из `.nvmrc`; кэш npm.
- Живые интеграционные сценарии (FT-0008) в CI не запускаются: им нужны учётные данные УрФУ. Офлайн-сценарии попадают в CI сами через `npm test`.

### Context (SSoT links)
- [EP-002](../epics/EP-002-automated-tests.md): риск про живые системы — интеграция только по требованию. Читать, чтобы не тащить учётные данные в CI.
- [Stack & tooling](../../spec/project/stack-and-tooling.md): команды и флаг `--legacy-peer-deps`. Читать, чтобы шаги совпадали с локальными.
- [Verification matrix](../verification-matrix.md): базовые проверки. Читать, чтобы CI проверял тот же набор.

### Implementation plan
- Секреты в workflow не нужны; если сборке web нужны переменные окружения — только несекретные.
- `git push` выполняет пользователь (блокирует хук), поэтому прогон на GitHub — последний шаг приёмки с участием пользователя.
- Сделано так: один job на `ubuntu-latest`, шаги в порядке Deliverables; `concurrency` отменяет устаревший прогон той же ветки; права — только `contents: read`.
- `react-scripts build` при `CI=true` (GitHub выставляет его сам) превращает warnings в ошибки, а у ESLint-правил проекта уровень warning, поэтому `web-build` падал. В шаге `web-build` задано `DISABLE_ESLINT_PLUGIN=true`: ESLint проверяет шаг `lint`, а остальные warnings webpack по-прежнему роняют сборку. Вариант `CI=false` отвергнут: он ослабил бы и эти проверки.

### Scenarios (acceptance)
#### Setup
- Ветка с workflow, запушенная пользователем; PR в `main`.
- Actors: разработчик.

#### Action
- Push ветки; затем push коммита с падающим тестом (коммит с `--no-verify` делает пользователь, только для проверки).

#### Assert
- Первый прогон зелёный, все шаги из Deliverables выполнены.
- Прогон с падающим тестом красный, падает шаг `npm test`.
- Прогон с ошибкой типов только в `*.test.ts` красный, падает шаг `npm run typecheck`.

### Tests
- Автотестов нет: инфраструктура, проверяется сценарием выше.
