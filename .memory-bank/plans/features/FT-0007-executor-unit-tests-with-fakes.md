## Feature FT-0007 — Unit-тесты исполнителей на фейковых адаптерах
Epic: `EP-002`. Status: `Planned`.
Triage: `needs-triage`.
Blocked by: FT-0006, FT-0010.

### User value
Поведение исполнителей заданий проверяется без реальных систем УрФУ и без учётных данных, на каждом коммите. Главное: доказано, что в try исполнитель не вызывает ни одной операции записи.

### Deliverables
- In-memory фейки портов БРС, ИТС и TeamProject (порты — из FT-0010): состояние задаётся в тесте, вызовы записи регистрируются.
- Unit-тесты оркестрации каждого исполнителя из каталога: разбор параметров и строк, события и `summary`, try против save.
- Инвариант для всех исполнителей: в try фейк не получает вызовов записи; в save — получает ровно для расхождений.
- Правила отдельных заданий (расчёт плана изменений) здесь не тестируются: это core-фичи FT-0012…FT-0014 (EP-003).

### Implementation plan
- `needs-triage`: фича зависит от интерфейсов FT-0010, которые ещё не описаны; после описания FT-0010 уточнить состав фейков и перевести в `ready-for-agent`.

### Scenarios (acceptance)
#### Setup
- In-memory сетка задания; фейк системы с состоянием, где часть объектов совпадает с листом, часть расходится.
- Actors: тест.

#### Action
- Запустить исполнитель в try, затем в save.

#### Assert
- Try: события `changed` для расхождений и `unchanged` для остальных; фейк не получил вызовов записи.
- Save: вызовы записи ровно для расхождений; повторный save по новому состоянию фейка даёт только `unchanged`.

### Tests
- Unit: исполнители каталога на фейках.
