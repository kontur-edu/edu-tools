# FT-0001 — Секреты вне кода
Status: Draft (2026-09-23)

## Feature FT-0001 — Секреты вне кода
Epic: `EP-001`. Status: `Planned`.
Triage: `ready-for-agent`.

### User value
Разработчик и ИИ-агент запускают Node-код, не правя исходники ради учётных данных, а в git не попадают `sid`, токены и куки. Это предусловие для CLI (FT-0003): команды берут учётные данные из одного места.

### Deliverables
- Загрузка учётных данных Node для БРС (`sid`), ИТС, TeamProject (JWT), Partner (cookie) из переменных окружения / `.env`, с возможностью указать файл в `secrets/`. Одна точка чтения, которой потом пользуется CLI.
- Понятная ошибка, если учётных данных системы нет: какая система и какую переменную (или файл) задать. Значение секрета в ошибке и логах не выводится.
- Из `src/main.ts` и `src/putMarks.sample.ts` удалены захардкоженные `sid`, токены и куки (они уже истекли, ротация не нужна); функции получают учётные данные из загрузчика.
- `.env.sample` дополнен именами новых переменных с пустыми значениями.

### Implementation plan
- Загрузчик — Node-only модуль (использует `fs` / `process.env`), не импортируется из кода, общего с web (guardrail 2).
- Имена переменных — по системе (`BRS_SID`, `ITS_AUTH`, `TEAMPROJECT_JWT`, `PARTNER_COOKIE` или аналогичные; окончательные имена зафиксировать в `.env.sample`).
- Существующие `secrets/brs*.json` не ломать: если формат удобен, поддержать чтение `sid` из файла.
- Google OAuth (`secrets/google.json`, `google-tokens.json`) остаётся как есть — это FT-0003 (`google login`).
- Проверить, что в истории коммита нет новых секретов (`git diff` перед коммитом).

### Scenarios (acceptance)
#### Setup
- `.env` без переменной для БРС; ИТС задана.
- Actors: разработчик.

#### Action
- Вызвать Node-код, которому нужен клиент БРС, затем клиент ИТС.

#### Assert
- Для БРС — ошибка с именем системы и переменной, без stack trace пользовательского уровня; для ИТС клиент создаётся.
- Поиск по `src/` не находит строковых литералов `sid`/токенов/кук, кроме пустых значений и имён переменных.

### Tests
