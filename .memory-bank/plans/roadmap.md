# Roadmap (epics order)
Status: Draft (2026-09-24)

Принцип: сначала делаем систему проверяемой (CLI, наблюдаемость, тесты), затем перестраиваем слои под защитой тестов. Функциональные эпики идут параллельно, когда готовы их описания.

## Порядок
1. [EP-001 — CLI и наблюдаемость](epics/EP-001-cli-and-observability.md). Первым, потому что убирает секреты из кода и даёт ИИ-агенту и разработчику способ запускать задания и получать машиночитаемый результат. Без этого нечем проверять остальное.
2. [EP-002 — Автотесты](epics/EP-002-automated-tests.md). Рабочий pre-commit (FT-0017) и unit-инфраструктура на Vitest (FT-0006) уже сделаны; интеграционные тесты на CSV-фикстурах — после CLI.
3. [EP-003 — Слои и вертикальные слайсы](epics/EP-003-layers.md). После того как появились тесты, которые страхуют рефакторинг. Порты из EP-003 нужны для unit-тестов исполнителей с фейками — эти фичи EP-002 и EP-003 делаются вместе.

## Перспектива (эпики ещё не описаны)
- **Partner:** расширение функциональности для `partner.urfu.ru` — описание эпика даст владелец продукта.
- **Скрипт Partner → Notion** (`cloneProjects`): не развивается; удалить или переписать с заменой Notion на BuildIn.AI.
- **Перенос brs-extensions:** базовый перенос баллов — табличное задание `PutMarksToBrs` (FT-0005, EP-001). Остаётся перенести возможности, которых в нём нет: колонка «auto»/«баллы» с распределением итогового балла, конфиг из названия таблицы и несколько курсов на листе, группа по префиксу и автоопределение, раздельные колонки ФИО, дополнительные исключения студентов, повторная проверка записи. После переноса решить судьбу `brs-extensions/`.
- **Замена Telegram-бота:** перенести сценарий «сохранить ресурс в Notion» в web-приложение или PWA и разобрать бота.
- **Переезд с Create React App на Vite:** CRA (`react-scripts` 5) больше не развивается и объявляет peer-зависимость на TypeScript 4 при TypeScript 5 в проекте, поэтому зависимости ставятся только с `--legacy-peer-deps` (см. [Stack & tooling](../spec/project/stack-and-tooling.md)). Затрагивает `web-start` / `web-build`, `public/index.html`, деплой web (`web-deploy.sh`) и общий `src/`, который собирают и CRA, и `tsc`. Лучше после EP-002, чтобы переезд страховали тесты; выбор раннера в FT-0006 стоит делать с оглядкой на Vite.
- **Обновление Node:** перейти на последние версии Node (включая runtime функции бота, сейчас `nodejs18`). Не сейчас: переход может сломать сборку и деплой.
